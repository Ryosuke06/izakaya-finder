## 2. 現在の課題

1. Langfuse 連携が途中実装

- `traceId`, `traceUrl` を state に持てるが、レスポンス state への反映は未整理
- `src/app/api/izakaya/search/route.ts` には Langfuse callback 呼び出しがある
- 環境変数未設定時の扱い、命名 typo、trace URL の返却方法は次に整理する

2. 返却 JSON の品質確認

- API Route からレスポンスが返る状態になったため、`candidates`, `ranked`, `reasons`, `summary` の内容確認が必要
- 現状の候補収集は LLM 生成のため、店名・住所・Google Maps URL の実在性確認が必要

3. Go backend の未実装・未検証

- `backend/` の実ファイルは未追加
- ローカル環境に `go` コマンドがないため、実装後の `go test ./...` は Go インストール後に行う

4. 結果表示と streaming 設計

- 検索ボタン押下後は、検索リクエストを `Search` レコードとして保存し、`/results/[id]` へ redirect する方針
- 結果ページは Server Component で server repository から request / result を読み取り、生成中表示は Client Component に分離する
- 現在は非 streaming 版の結果表示を先に完成させる方針
- `findSearchResultById` は `SearchStateSchema.parse(search.result)` の結果を返却済み
- 存在しないIDの扱いは repository で `throw` するより、`null` を返して `src/app/results/[id]/page.tsx` 側で `notFound()` を呼ぶ設計へ寄せる
- 段階的な AI 生成表示は AI SDK `streamText` を使う方針
- streaming 用 Route Handler は `src/app/api/results/[id]/stream/route.ts` を想定する
- 生成完了後、最終結果を `Search.result` / `Search.summary` に保存する

5. 未追跡ファイル

- `smple.json`
  - サンプル検索結果らしき JSON が未追跡で存在する
  - 現在は複数の JSON 値が連結されており、JSON として構文エラーである
  - 用途を決める必要がある
  - 残す場合は `sample.json` などへ typo 修正し、fixture として置く場所を決める
  - 不要なら削除する
