## 2. 現在の課題

1. Langfuse 連携が途中実装
- `traceId`, `traceUrl` を state に持てるが、レスポンス state への反映は未整理
- `app/api/izakaya/search/route.ts` には Langfuse callback 呼び出しがある
- 環境変数未設定時の扱い、命名 typo、trace URL の返却方法は次に整理する

2. 返却 JSON の品質確認
- API Route からレスポンスが返る状態になったため、`candidates`, `ranked`, `reasons`, `summary` の内容確認が必要
- 現状の候補収集は LLM 生成のため、店名・住所・Google Maps URL の実在性確認が必要

3. Go backend の未実装・未検証
- `backend/` の実ファイルは未追加
- ローカル環境に `go` コマンドがないため、実装後の `go test ./...` は Go インストール後に行う

## 3. 直近でやること（再開手順）

1. `docx/app-spec-draft.md` を先に確認（必須）
2. API Route + Langfuse の最小完成に着手する
- `POST /api/izakaya/search` を実際に1回通す
- Langfuse 環境変数が未設定でも検索 API が壊れないようにする
- `createLangfudeCallback` / `izakayaLangGtaph` などの typo を整理する
- 可能なら `traceId` / `traceUrl` をレスポンス state に含める
3. 返却 JSON の内容を確認する
- `candidates` が 5〜10 件程度返っているか
- `ranked` が `score` 順に並んでいるか
- `reasons` が入力条件に合った説明になっているか
- `summary` が自然な日本語で、入力条件に触れているか
4. 候補の実在性改善方針を決める
- `fetchCandidates` を Google Places API などの実データ取得へ寄せるか検討する
5. Go backend の最小実装方針を確定する
- `backend/` に標準ライブラリのみで配置するか確認する
- AWS Cognito はまず設定受け口のみ作るか確認する
6. Go backend 実装後に検証する
- `cd backend && go test ./...`
- `cd backend && go run ./cmd/server`
- `curl http://localhost:8080/health`
- `curl "http://localhost:8080/stations/suggestions?q=渋"`
7. UI から Go backend の駅サジェストを呼び出す
8. Cognito JWT 検証を Go backend に追加する
